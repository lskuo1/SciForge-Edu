# Sprint 004 — Engineering Contributor Guide

Status: Completed

---

# Objective

Establish a canonical engineering entry document for contributors to the
SciForge-Edu repository.

The objective of this sprint is not to introduce new engineering policies,
but to improve repository discoverability, contributor onboarding, and AI
transferability.

---

# Background

Previous governance work established:

- Engineering Change Governance Policy
- Implementation Plan Template
- Repository governance workflow

However, the repository lacked a single entry document explaining:

- how contributors should understand the repository;
- how repository knowledge is organized;
- how engineering work is navigated;
- where engineering information can be found.

This sprint addresses that gap.

---

# Scope

## In Scope

- Create the Engineering Contributor Guide.
- Define repository orientation.
- Define repository discovery.
- Introduce engineering navigation.
- Improve contributor onboarding.
- Improve AI onboarding.
- Review the guide through independent architecture reviews.

## Out of Scope

- Runtime implementation.
- Parser changes.
- Repository behavior.
- Renderer.
- GUI.
- Import pipeline.
- Repository metadata governance.
- Artifact authority model.

---

# Deliverables

The following deliverables were completed.

- Engineering Contributor Guide.
- Independent document review.
- Independent repository review.
- Architecture review resolution.
- Repository consistency improvements.

---

# Validation

The Engineering Contributor Guide was reviewed from multiple perspectives.

Validation activities included:

- Architecture review.
- Independent document review.
- Repository-wide architecture audit.

Review findings were incorporated where consistent with the repository
architecture.

Repository issues unrelated to the guide were intentionally deferred.

---

# Repository Impact

This sprint introduces the Engineering Contributor Guide as the canonical
engineering entry document.

The guide is responsible for:

- repository orientation;
- repository discovery;
- engineering navigation;
- contributor onboarding.

It intentionally avoids replacing governance policies or engineering
templates.

---

# Deferred Topics

The following observations were intentionally deferred to future work.

- Repository artifact authority.
- Repository metadata governance.
- Document lifecycle model.
- Repository knowledge lifecycle.
- Automated repository navigation.
- Current Status maintenance process.

These topics require broader repository evolution and are outside the scope
of Sprint 004.

---

# Success Criteria

Sprint 004 is considered successful if:

- contributors can understand repository organization from a single entry
  document;
- AI sessions can discover repository knowledge without relying on previous
  conversations;
- engineering governance remains centralized in the governance policy rather
  than duplicated.
