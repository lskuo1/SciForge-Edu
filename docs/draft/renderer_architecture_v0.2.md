# Renderer Architecture v0.2

Status:

Draft

## Purpose

Define the responsibilities, boundaries, and internal workflow of the Renderer subsystem.

The Renderer subsystem transforms parsed Question objects into standalone publication-ready LaTeX documents and PDF outputs.

Renderer is a production subsystem.

Renderer is not responsible for question parsing, repository management, curriculum analysis, or educational diagnostics.

---

## Responsibilities

Renderer is responsible for:

* Render namespace assignment
* Resource collection
* Asset packaging
* Label rewriting
* Ref rewriting
* Template loading
* Template rendering
* Exam document generation
* Answer sheet generation
* Teacher version generation
* PDF compilation
* Output artifact management
* Figure synchronization

Examples:

* student.tex
* teacher.tex
* answer_table.tex
* PDF outputs
* standalone output bundles

---

## Non-Responsibilities

Renderer must not perform:

* Question parsing
* Repository indexing
* Repository import workflows
* Duplicate detection
* Similarity detection
* Knowledge point analysis
* Curriculum mapping
* Educational diagnostics

These concerns belong to upstream subsystems.

---

## Current Scope

Renderer v0.2 supports:

* LaTeX rendering
* XeLaTeX compilation
* Output bundle generation
* Resource discovery
* Asset packaging preparation

Renderer assumes:

* Questions are already parsed
* Question objects are valid
* Question Identity already exists

---

## Design Principles

### Output-Focused

Renderer focuses exclusively on output generation.

Input preparation belongs to upstream subsystems.

---

### Self-Contained Output

Generated output should be independently compilable.

All required resources should be packaged into the output bundle.

---

### Stable Identity, Temporary Namespace

Question Identity and Render Namespace are separate concepts.

Question Identity is stable.

Render Namespace is temporary.

---

## Question Identity

Question Identity is associated with a Question object.

Question Identity:

* is generated before rendering
* remains stable across render operations
* remains stable across answer balancing
* remains stable across question reordering
* may be used by repository workflows
* may be used by statistics systems

Renderer consumes Question Identity.

Renderer does not generate Question Identity.

Question Identity should not be exposed directly in rendered output.

---

## Render Namespace

Render Namespace is generated by Renderer.

Examples:

```text
q0001
q0002
q0003
```

Render Namespace is used for:

* LaTeX labels
* LaTeX refs
* asset naming
* renderer-internal references

Render Namespace:

* may change between render operations
* depends on render ordering
* is not persistent

---

## Namespace Map

Renderer generates a namespace map.

Example:

```python
{
    question_uuid_1: "q0001",
    question_uuid_2: "q0002",
}
```

The namespace map is shared across:

* AssetPackager
* LabelRewriter
* RefRewriter
* TemplateRenderer

A single render operation should use exactly one namespace map.

## Resource Collection

ResourceCollector discovers external resources referenced by questions.

Examples:

* images
* figures
* diagrams

Responsibilities:

* detect resource references
* resolve paths
* preserve provenance information

ResourceCollector does not copy files.

---

## Asset Packaging

AssetPackager is responsible for:

* copying resources
* renaming resources
* avoiding filename collisions
* generating asset mappings

AssetPackager consumes:

* ResourceCollector output
* namespace map

AssetPackager shall not generate Render Namespace identifiers.

Example:

```text
acid.png

↓

assets/q0001_acid.png
```

---

## Label Rewriting

LabelRewriter is responsible for generating renderer-local label names.

Example:

```latex
\label{fig:acid}
```

↓

```latex
\label{q0001_fig_acid}
```

The original source file should not be modified.

---

## Ref Rewriting

RefRewriter updates all label references to match rewritten labels.

Example:

```latex
\ref{fig:acid}
```

↓

```latex
\ref{q0001_fig_acid}
```

Label rewriting and ref rewriting must remain synchronized.
