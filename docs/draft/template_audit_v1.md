# Purpose

This document records observations about the
current legacy template architecture.

The goal is to distinguish:

* renderer responsibilities
* template responsibilities
* exam class responsibilities

before major template refactoring begins.

# Observation 001

## The \ifprintanswers block is not duplicated content

Current template structure:

```
\ifprintanswers
    ...
    [[ questions_content ]]
    ...
\else
    ...
    [[ questions_content ]]
    ...
\fi
```

At first glance this appears to duplicate
question content.

However:

* teacher version uses single-column layout
* student version uses two-column layout

The block is therefore primarily a layout
switching mechanism.

Conclusion:

Keep this structure for now.

---

# Observation 002

## Question content is injected only once

Questions are generated by:

```
ExamRenderer
```

and inserted through:

```
[[ questions_content ]]
```

The template does not generate questions.

The template only controls layout.

Conclusion:

Question rendering belongs to the renderer
layer.

---

# Observation 003

## Solution visibility is controlled by exam.cls

Renderer currently emits:

```
\begin{solution}
...
\end{solution}
```

for questions that contain solutions.

Visibility is then controlled by:

```
\printanswers
```

or

```
\noprintanswers
```

provided by exam.cls.

Conclusion:

Current system delegates solution visibility
to the LaTeX layer.

---

# Observation 004

## Student and teacher documents are separate files

SciForge-Edu currently generates:

```
student.tex
teacher.tex
```

This differs from many legacy workflows where
a single document is compiled twice using
different flags.

Conclusion:

Some legacy mechanisms may eventually become
unnecessary.

However no removal should occur before the
template architecture is fully understood.

---

# Observation 005

## Layout and answer visibility remain coupled

Current behavior:

Teacher:

* single column
* answers visible

Student:

* two columns
* answers hidden

These are two independent concerns:

1. Layout
2. Answer visibility

Future architecture may separate them.

Examples:

* teacher two-column version
* student single-column version
* answer key sheets

This is a future enhancement.
